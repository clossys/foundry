Adds `readEngagementContext` and `readEngagementContextFromBriefData` (issue #1173), which read the shared engagement context from a consumer's own `clossys/brief.json`, validated against the same shared brief contract (issue #1475: `docs/contracts/engagement-brief.json` with `engagement-context.json`) `@clossys/advisor` and `@clossys/launcher` validate against. This package's build (`scripts/pack-brief-contract.mjs`) packs a generated, gitignored copy of those two contract files and of their one checker (`packages/advisor/src/contract-schema.ts`) into `src/generated/`, so Strategist validates against the same definition with no `dependencies` entry on `@clossys/advisor`. Reading is all-or-nothing: a brief that does not fully validate reads as every field unknown, the same as no brief at all, with a note naming only a fixed reason, an OS error code, or a JSON syntax position — never file text or founder text, and never a value read from a field that happened to look fine inside an otherwise invalid document. Adds `pendingAudienceIntakeQuestions`, which points the founder back to Advisor's own `audience` context card instead of asking a Strategist-owned rename of it, and otherwise asks Strategist's three questions specific to a named audience's situation and pains. Adds `seedAudienceFromContext`, which proposes a starting `audiences.json` entry from the brief's coarse `audience` field — its `situation` is a neutral sentence built from the choice id, not a copy of Advisor's own card label — and refuses to seed anything once `audiences.json` already has an entry, so a detailed record is never overwritten by a coarse brief guess. Updates the package README and skill to describe this.

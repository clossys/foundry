Adds `readEngagementContext` and `readEngagementContextFromBriefData` (issue #1173), which read the shared engagement context from a consumer's own `clossys/brief.json` as data, dependency-free of `@clossys/advisor` at runtime. Every field reads as unknown, never invented, when the brief is absent, has no `context` property yet, or does not match `docs/contracts/engagement-brief.json`'s or `docs/contracts/engagement-context.json`'s own required keys, allowed keys, `schemaVersion`, field count, or per-field shape; a note is returned whenever the brief or its context fails that match, naming only an OS error code for an unreadable file, never its message or path. Adds `pendingAudienceIntakeQuestions`, which points the founder back to Advisor's own `audience` context card instead of asking a Strategist-owned rename of it, and otherwise asks Strategist's three questions specific to a named audience's situation and pains. Adds `seedAudienceFromContext`, which proposes a starting `audiences.json` entry from the brief's coarse `audience` field — its `situation` is a neutral sentence built from the choice id, not a copy of Advisor's own card label — and refuses to seed anything once `audiences.json` already has an entry, so a detailed record is never overwritten by a coarse brief guess. Updates the package README and skill to describe this.

## What was built

All code extends the producer review engine. Nothing new lives in `packages/reviewer` beyond the skill text and a test hook.

- `packages/producer/src/review/cloud.ts` (new):
  - **(a) `publishGate`**: runs `runReview` at head with the packet and its receipt. It writes `gate.json` (`clossys.cloud-gate/1`: unit, base, mergeBase, head, tree, the packet's name, sha256 and parsed commands, receipt, full review record, verdict, `GATE:` line) and `receipt.json`. Those two files are committed with git plumbing (hash-object, mktree, commit-tree, update-ref) to `refs/heads/<unit>-gate`, stacked on the previous gate commit. `--push <remote>` pushes only that ref. Afterwards it checks that the unit branch, the index and the working tree are unchanged, and throws if not. Local paths (repo, packet dir, receipt dir, temp root, home) are replaced by `<local>`.
  - **(b) `importGate` / `judgeImport`**: re-runs nothing. Refusal ids: `import.malformed`, `import.head` (result, review or receipt head is not `--head`), `import.tree`, `import.base` (base is not `--base`, or the merge base differs or cannot be computed here), `import.dirty`, `import.no-commands`, `import.command-missing`, `import.receipt-skipped`, `import.inconsistent` (verdict disagrees with its own findings, fail-closed counts or line, e.g. a FAIL relabelled PASS). An accepted import writes the same `clossys.review/1` record a local run writes, plus an `imported` field.
  - **(c) Fallback**: a cloud FAIL imports as FAIL and writes the FAIL record. A refused or failed import names the next step: a local run, `clossys review <base> <head> --packet <unit.md>`.
  - **(d) `batchGate`**: takes imported PASS records whose heads are merged into the tip. It prints `BATCH: RERUN <tip>` with the one local re-run (`clossys review <base> <tip>`) and lists the commits no imported head reaches (made on this machine). It refuses an imported FAIL, a record that `--import` did not write, a head not merged into the tip, or an empty batch.
- `packages/producer/src/cli/review.ts`: adds the `--publish`, `--import`, `--batch` flags and their options to `clossys review`. These three are mutually exclusive, and their options are refused outside them.
- `packages/producer/src/review/types.ts`: optional `imported` field on `ReviewReport`.
- `packages/producer/src/review/doc.ts`: adds a "Cloud gate results" section. `packages/producer/docs/review.md` was regenerated by its verb, `clossys review --write-doc`; `--check-doc` exits 0.
- **(e) Rule**: `R-REVIEW-CLOUD-PROOF`, `owner_agent: reviewer`, `status: enforced`, check `.#check:cloud-proof` (`scripts/check-cloud-proof.mjs`).
  - Findings: `missing-rule` (skill text), `cloud-head-mismatch` (an imported record's head or tree is not the one it records), `cloud-fail-overridden` (an imported cloud FAIL recorded as PASS).

## D5 note: the parity fixtures are constructed, not recorded

The packet says the launch prompt attaches three recorded gate results with their `cloud-gate.py import` verdicts. This launch prompt attached none, and the unit is not allowed to read anything outside the repository. So the three fixtures are built to the packet's own description of each case, with synthetic shas and no private paths or names:

- one accepted (PASS);
- one refused for a head mismatch (`import.head`, `import.tree`, with a local run as the fallback);
- one cloud FAIL that falls back to a local run.

Each fixture's `provenance` field says so. The test "import matches the recorded cloud gate verdicts" therefore proves the import matches these specified verdicts. It does not yet prove a match with what `cloud-gate.py` actually recorded. Needed migration (planner): swap the three real recorded results, scrubbed, into the same files. The test's shape is `{ id, recorded: { status, refusals, fallback }, facts, gate }`.

The recorded base can be proven from the gate result alone, given the objects: the result records `base` and `mergeBase`, and import recomputes `git merge-base <recorded base> <head>` here. If it cannot, import refuses (`import.base`) rather than guessing. So no BLOCKED-D5 was raised.

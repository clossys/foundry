No engine elsewhere; Producer only routes `clossys heal` (`packages/producer/src/cli/heal.ts`, one `head === "heal"` line in `src/pipeline/runner.ts`) to `healMain` exported from the `@clossys/controller` root entry (no new subpath: the root comment explains the canary matrix keyed by export specifier).
- **(a) Record** (`signature.ts`, `types.ts`): `foundry.incident/1` = stage, command, exit, signature, at. The signature drops paths (with `:line:col`), shas, ISO/clock times, durations and bare numbers, and keeps numbers inside ids (`r2f`, `TS2307`, `h1`). `clossys heal run --stage <s> [--dir d] -- <cmd>` writes a record for any failing command, by default to `node_modules/.cache/incidents/`. `at` is the only field added beyond (a), and the verb writes it, so this is not D5.
- **(b) Causes as data**: `causes.json` holds the five seed causes. Each one has id, match (regex over `<stage>\n<signature>`), owner, remedy, blocker, guard and guard_landed.
- **(c) Heal** (`heal.ts`): a known cause with a remedy runs the remedy, re-runs the step exactly once and records `healed` or `still-failing` (written to `<record>.outcome.json`). When the remedy asks for it (`compareBase`), a red re-run is also run on the base with the same env object and cwd, and the same exit counts as healed. A remedy of `none` prints `BLOCKED <cause> owner=<agent>: <blocker>`. An unknown signature prints `NEW-CAUSE <signature>` and runs nothing.
- **(d) No repeats** (`report.ts`): `clossys heal --report [--since/--until]` prints `COUNT` per cause and `NEW-CAUSE` lines. A guarded cause recorded after `guard_landed` prints `REPEAT <cause> guard=<rule>` and exits 1. The root `check:heal` (added to root `check` after check:every-candidate-previewable) runs it over `src/loop/incidents/records/`: five seed records, one per cause, all dated before the guards landed, so it exits 0.
- **(e) Seed causes** — remedy → guard rule (all `.#check:heal`, each with a violation fixture under `scripts/rules/fixtures/`):
  - orphan-test-child (owner developer): `kill-orphan-groups`, which ends the groups of test-runner processes re-parented to init that run in this checkout, never its own group. Guard **R-FIXTURE-NO-ORPHAN**: probes `spawnFixture` (`spawn-fixture.ts`, which spawns detached and tears down the whole group with SIGTERM then SIGKILL). The probe spawns a parent that starts a SIGTERM-ignoring child, tears down, and fails if the child survives. Fixture: a spawner that kills only the parent.
  - fixed-exit-root-check (planner): `compare-with-base`. Guard **R-ROOT-CHECK-BASE-RELATIVE**: packet lint refuses `npm run check` held to a fixed exit.
  - load-noise-timeout (reviewer): `rerun-alone-then-base`. Guard **R-NEW-RED-CONFIRMED**: a reds report may call a red `new` only after it failed alone and passed on the base (`classifyRed`).
  - stale-branch-ref (planner): `fetch-then-compare`, which fetches every branch the step names, then re-runs. Guard **R-FOLD-FETCH-FIRST**: a fold plan may not compare a branch before fetching it.
  - contradictory-packet (planner): remedy `none`, documented. Picking either expectation in code would either relax a check or refuse a sound unit, so the planner rewrites the packet. Guard **R-PACKET-ONE-EXPECTATION**: packet lint refuses one command with two expectations.

That rule is registered as **R-HEAL-CAUSE-GUARDED** (owner planner). `check:heal` refuses a cause with no guard, a guard that is not an enforced registry rule, or a remedy that is neither code nor `none`. **R-HEAL-NO-REPEAT** (owner controller) registers (d). The owned-rules blocks in the planner and reviewer skills list their new rules.

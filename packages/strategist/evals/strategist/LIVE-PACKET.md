# Kilnpad live evaluation packet

This is a procedure, with no live result recorded. Use native subscription agents only; never use a paid model API or start a new login. Model names are not role tiers, and requested settings do not prove the serving configuration.

Three independent contexts are required: a high-tier strategist, a mid-tier simulated user and a fresh high-tier judge. A coordinator relays their exact messages. The implementing executor may capture files and run scripts, but must not write the simulated user's answers or judge its own interview. If a tier is unavailable, report pending evidence; never substitute authored fixture transcripts.

## Strategist handoff

Read the integrated `packages/strategist/skill/SKILL.md`, its role prompts, and the catalog. Until ST-8 is integrated, the approved packet at `packages/strategist/docs/v2/skill/SKILL.md` is the reference, and the run remains provisional. Start with an empty strategy root in an operator-selected scratch directory, never a real consumer repository. Record the exact source commit and root snapshot. Speak only as strategist. Interview the independently supplied simulated founder of fictional ceramics software Kilnpad. Keep session logs verbatim, create cells and requests only under this root, use the listed batch-confirm protocol, and follow the cell model. Ask one question per turn. Do not read the hidden user persona, expected or traps files. Stop at measured product-saas MVS or 60 user turns, and state any unmet criteria. Call a separate fresh critic at the new Bet and before MVS as the skill requires. Without that helper label self-critique honestly; the judge will score the limitation.

## Simulated user handoff (mid tier, independent)

Read only `kilnpad/persona.md` and `kilnpad/traps.json` in this directory. Speak first person as that fictional founder. Start with the studio problem and answer the strategist's single question each turn. Reveal facts naturally; plant traps on the specified user turns. Do not author cells, evaluate the strategist or invent evidence. The coordinator supplies the strategist's exact next message. Continue until MVS or 60 user turns, preserving ambiguous and partial confirmations as scheduled. Do not read expected.json or the rubric before the interview ends.

## Fresh judge handoff (high tier)

After the interview ends, start a fresh context. Read `rubric.json`, `kilnpad/expected.json`, `kilnpad/traps.json`, the entire verbatim transcript, activation timeline, all strategy files including retired versions, and raw CLI captures. Do not converse as the founder or strategist. Score the six judge criteria from the anchored rubric: hypothesis-first, options-before-choices, pushback, pre-mortem, routing, contradiction-handling. For each supply `{score: 0|1|2, evidence: ["S<n>", ...], reason: "..."}` with actual supporting transcript lines. Zero is required for a silent active edit or auto-activation of a contradiction fix. Judge Q/C flags separately; no pending judge finding counts as a completed pass. Review claimed levels against measured completion and critic evidence. Return the judge section with `kind: "fresh-high"` and its distinct session identifier, plus any observed violations. Never infer a live result from the synthetic scorer fixtures.

## Evidence required by the coordinator

Preserve the native session identifiers, requested tiers, any observed runtime settings (unknown when unproven), exact source heads, ordered U/S lines, per-activation `{ref, confirm: "U<n>", after: "U<n>|S<n>"}` events and final active refs. Record every activation including those later retired. Save raw `strategist-check` output for `check` (each active cell), `cohere`, `complete --level mvs`, `complete --level full` and `status`, all with `--root` and `--json`, command arrays and exit codes. Save the root snapshot and judge response. Do not strip failed commands. CLI read failures are missing evidence, never clean results.

The scorer aggregates normalized CLI measurements; it is not itself a semantic judge or proof of session authenticity. Do not fabricate measurements while ST-3/CLI integration is pending. RUN.md describes normalized fields. The adapter is normalized against integration 3890f9e0. The CLI writes report files and leaves Q/C judgments pending; preserve that limitation for the fresh judge. The scorer reads the raw capture and does not accept manually substituted clean measurements. Report the live result and score in the authorized receipt/evidence destination; creating a public PR is not part of this packet.

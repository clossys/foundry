# Applying consumer library decisions

Build Designer, then invoke the standalone entrypoint:

```sh
node dist/library-cli/library-apply-decisions.js ./library \
  --catalog ./offline-catalog.json \
  --bundles ./source-bundles.json \
  --component-options ./component-observations.json
```

`--catalog` supplies a `CompositeCatalogData` JSON document, including the exact
candidate descriptors. `--bundles` supplies already materialized `SourceBundle[]`
for source components; package pointers need no bundle. `--component-options`
supplies independently collected component observations and package-export
inventories. No observations are generated by this command. A fill with no
supplied observation is runtime-pending: its K2/K4/K5/K6/K7/K10/K12 findings are
notices, the selection is recorded, and emitted consumption reports
`runtime-pending`, never `observations-pass`. Supplied observations that fail,
or omit a mapped member, remain failed checks, and package fills still need
their declared package exports. These inputs are local files; the command never fetches a
URL or installs a package. There is no package bin registration yet.

The folder must already use the library CLI disk layout. Its `decisions.json`
is an array with at most 256 rows, one per slot, in dependency order. Every row
requires `slot`, `kind` and a nonempty `note`. Unknown keys and duplicate slots
are rejected. Supported rows are:

| kind | tokens/assets | components |
| --- | --- | --- |
| `adopt` | `source`, optional exact candidate id `fill` | Same; source implementations also require a verified bundle |
| `author` | `value`: map of relative member names to DTCG token objects | `fill`: complete component descriptor, `files`: component file array |
| `derive` | registered `rule`, `reads`: full token member ids | registered `rule`, `reads`: component slot ids |
| `compose` | Unsupported | registered `rule`, `reads`: component slot ids |

For example, an authored value row is:

```json
[
  {
    "slot": "tokens.body-size",
    "kind": "author",
    "value": { "default": { "$type": "dimension", "$value": { "value": 14, "unit": "px" } } },
    "note": "Approved body size"
  }
]
```

Rows compile into one ordered `CompositeChangeSet` and use the existing engine.
A source `fill` selects an exact candidate id; it cannot bypass the unique
candidate requirement. Rule reads must match the registered component rule.
Source pin, licence, descriptor and output-hash checks remain engine checks.
Programmatic callers may use `materializeDecisionBundles` with supplied upstream
bytes and registered transforms; its fetch port reads only that supplied array.

The L-2 reader, lock, stale-base check, composite check, disk projection and
atomic persistence form the write boundary. A failed batch leaves the library
unchanged. Reapplying identical decisions returns the same hash and skips the
disk swap. The JSON result reports `baseHash`, `hash`, `changed` and row count;
exit codes are 0 for success, 1 for a stale base or failed library check, and 2
for invalid input or an unavailable file/source/transform. Fills and generated
selection are outputs; `decisions.json` is retained as the input record.

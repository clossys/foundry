## Root cause and change

`clossys init` already adopts and pins every placed agent's loops (`packages/producer/src/cli/init-loops.ts`,
which calls `adoptAndPinAgentLoops` from `cli/loop.ts`). `init-u20.test.ts` already covers a fresh consumer and
a re-run. The gap was the consumer fixture that conform reads: it held none of the loop slots.

That fixture is the output of `packages/producer/scripts/seed-pinned-world.mjs`, and `pinned-world.test.ts` requires
it to be byte for byte one seeder pass. So the verb runs inside the seeder, not by hand:

- `seed-pinned-world.mjs`: the new last step `adoptLoops` runs `clossys loop <agent>/loop.scope --by planner:package-default --at AT`
  for director, designer and writer (the agents whose IA places slots; Publisher's IA places none). It adopts each
  agent's five loop slots and pins them through the pin gate, the same adoption init runs. Nothing is deleted.
- Fixture regenerated with `node scripts/seed-pinned-world.mjs`: 15 loop slots (slot, ledger, candidate, pin),
  three ia.json and ledger.json files, and `.state` scorecards, index and events.
- Re-running the verb writes nothing: after `clossys loop <agent>/loop.scope` ran a second time on the fixture,
  `git diff` showed 0 lines.

Tests updated for the adopted fixture (no check logic, scanner, allowlist, baseline or ceiling changed):
- `conform/conform.test.ts`: W2 is now asserted green with no rows for every agent. Before, it pinned the red.
- `cli/loop.test.ts`: the new `unadopted()` helper restores a copy to its pre-adoption bytes. It removes the loop
  slots, the loops node, layer and axis values, and the adopt-loops ledger event; I checked that this gives back
  the base ia.json and ledger.json exactly. The four tests that exercise adoption from an un-adopted consumer use it.
- `loop/code-pin.test.ts`: the widened confirm step is pinned on designer's own adopted loop.choose through the pin
  gate, since that is now the consumer's own loop for the hero.
- `conform/contract-fixtures.test.ts`, `records/slot-model/option-classes.test.ts`: loop slots and the loops node
  are left out of the content-slot and content-group listings, as conform's model already does.

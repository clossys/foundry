### The P5 regression (why this unit is BLOCKED)
P5 rows: `queue.change#<id>: open, no waiting run holds it, and its subject (none) is no slot or publication a run can start from`.
The P5 entry reader (packages/producer/src/conform/producer.ts, readEntries) takes an entry's subject only from
the clossys.queue-entry/1 field `subject.to`. A clossys.queue-entry/2 change entry names its slot in `target`, and the
/2 schema (additionalProperties false) has no `subject` field. So any open /2 change or fix entry in the conform
fixture turns P5 red, and the entries Q2 needs are exactly such entries. Only two things would keep P5 green: a check
change (have readEntries also read `target`), which this unit's rules forbid, or fabricated waiting run states, which
would be false data. Neither was done.

## Change
- packages/producer/src/pipeline/interview.ts: `fileInterviewNeeds(root, gaps, at)`. For each request gap that no
  open entry records (none targets its item or one of its need slots), it files an entry through the existing write
  path: `raiseWork` kind change (want repin/candidate/contract by gap code) on the upstream slot, from the first
  downstream slot that cites it, or `raiseRequest` kind slot for request.slot-missing. A refusal is reported, and
  nothing is written for it. It is idempotent because it dedupes against open entries. The Director-entry gap code
  now comes from a per-kind table (request.director-slot/change/fix), since that gap is the open entry itself, and
  its `need` is now the requester slot (the documented meaning of `need`) rather than its own target.
- packages/producer/src/cli/next.ts: `next --owner` files the scoped gaps first, then prints. The output gains
  `filed: {created, refused}`.
- Fixture packages/producer/test-fixtures/consumer: the 14 queue.change entries (plus their .state events) were
  written by running `clossys next --owner` against the fixture. Running it a second time created none.
- Test: interview.test.ts "next --owner files every request need it prints as a queue entry, once (Q2)".
